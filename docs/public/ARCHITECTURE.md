# Архитектура (публично) / Architecture (public)

Высокоуровневая схема **без исходников**. Для пользователей и аудита доверия.

High-level design **without source code**.

---

## Обзор / Overview

```
┌─────────────────────────────────────────┐
│  Electron UI  (public/ HTML·CSS·JS)      │
│         ↕  HTTP 127.0.0.1               │
│  Local API (Express)                    │
│         ↕                               │
│  sing-box.exe  →  TUN thes-tun          │
│         ↕                               │
│  Node from subscription / free catalog  │
└─────────────────────────────────────────┘
         ↕
   %AppData%\Thes\  (settings JSON)
```

## Поток подключения / Connect flow

1. Пользователь нажимает **Подключить**.
2. Проверка конфликтов (Happ / другие TUN).
3. Выбор ноды (ручной или авто / failover).
4. Генерация конфига sing-box → старт ядра с правами администратора.
5. TUN поднимается; split или full по настройкам.
6. Watchdog следит за dial; при мёртвой ноде — смена сервера (если включено).

## Split vs Full

| | Split | Full |
|---|--------|------|
| Сайты / приложения | Только список | Весь трафик |
| Остальное | Direct (напрямую) | Через ноду |
| Kill-switch | Обычно не нужен | Опционально |
| Нагрузка на роутер | Ниже (особенно с локальным DNS) | Выше |

## Конфликт с Happ

Happ поднимает свой TUN (`happ-tun`). Два системных туннеля на одном ПК часто ломают DNS и домашний Wi‑Fi. Thes **блокирует** подключение, пока Happ активен, и предлагает закрыть мешающий VPN.
